# Motion Deck — 網頁動態簡報

把這份簡報當成你的作品展示卷（reel）：它要證明你是一位多麼出色的動態設計師。請全力以赴。

不要做「加了動畫的投影片」，要做「可以一頁一頁停下來閱讀的動態影片」。沒有模板、沒有預設手法——每一個轉場、每一條曲線、每一段節奏都是你為這個主題做的設計決定。最好有一個讓人看完還記得的招牌時刻。

## 唯一的硬性限制

> **靜止即完整，轉場即表演。**

- **靜止**：轉場結束後，該頁所有資訊必須完整、清晰、可閱讀。只允許不干擾閱讀的細微動態，文字本體不動。
- **轉場**：你的舞台，沒有任何限制。

這是為了讓簡報能被截圖、轉傳、閱讀。除此之外，設計完全自由。

## 工作流程

### 1. 詢問（開始前一次問完）

用 AskUserQuestion 提問。

**A. 內容（必問）**

1. **主題**：這份簡報講什麼？
2. **對象**：給誰看？
3. **內容來源**：使用者提供資料／檔案，還是由你撰寫？若使用者提供，先完整閱讀素材。

**B. 設計偏好**：風格、頁數、配色、字體。每題給 2–3 個依主題與對象量身挑選、彼此差異明顯的選項，並一律附上「由你決定」。

- 使用者選「由你決定」的項目，自行判斷，不再追問。
- 使用者已在需求中指定的項目不要重問；若使用者表明全部交給你，跳過 B。
- 選項只定大方向，細節仍由你設計。

**轉場與動態手法不詢問**——那是你發揮的地方，只要與選定的風格協調。

### 2. 設計提案

用幾行告訴使用者你的概念（視覺隱喻與動態方向），然後直接開始製作，不必等確認。

### 3. 製作

- 以 `assets/deck-engine.html` 為起點。它**只有基礎建設**（舞台縮放、翻頁、網址錨點、轉場鎖、降級、reduced-motion），沒有任何視覺或動態設計——轉場、進場、版面、細微動態全部由你親手寫。API 說明在檔案開頭註解。
- 動手前讀 `references/motion-principles.md`（細微動態上限與實作上容易踩的坑）。
- 任何技術都可以用：GSAP 與其所有外掛、SVG、Canvas、WebGL／Three.js、CSS——選最能表達概念的。函式庫與字體走 CDN（`cdn.jsdelivr.net`、`cdnjs.cloudflare.com`、Google Fonts）。
- 輸出單一 `.html` 檔，存在目前工作目錄，檔名用主題的英文 kebab-case，例如 `ai-trends-2026.html`。

### 4. 自我驗收

依 `references/quality-checklist.md`：先確認硬性限制與健全性全過，再用作品集的標準挑出最弱的一處重做。有 Node 的話用截圖實際看過每一頁的靜止畫面與轉場過程影格。

### 5. 交付

告訴使用者：檔案路徑、操作方式（← → / 空白鍵 / 滑動 / F 全螢幕）、一句話的設計概念。不要貼出整份程式碼。

## 避開平庸

- 每個元素都「淡入＋上移」就是模板感；每頁都置中、每次轉場都一樣也是。
- 卡片堆疊的 dashboard 風不是動態設計。
- 內容很多時（例如甲方要求）以資訊完整優先，用版面層級與字級對比維持可讀，不刪內容。
